# Faith 음성 모델 서버 실험

새 모델 추론과 벤치마크는 로컬 장비에서 실행하지 않는다. 로컬에서는 소스 문법 검사,
기존 캐시 재평가, 결과 보고서 생성만 허용한다. 실제 음성 입력을 모델에 넣는 실행은
임대 서버 작업으로 제한한다.

## 실행 원칙

- 기본 실행 환경: GCP Cloud Run Job, `asia-southeast1`
- 작업당 `tasks=1`, `parallelism=1`, `max-retries=0`
- 실행 전에 시간 제한과 시간당 단가로 최대 비용을 계산한다.
- 공개 KTV fixture와 오픈 가중치는 전용 비공개 버킷만 사용한다.
- 고객 음성, API 키, Hugging Face 토큰은 이미지에 포함하지 않는다.
- 임대 클라우드 실행은 비공개 프로젝트 안에서 처리해도 `외부 전송=예`로 기록하고,
  외부 모델 API 호출 여부와 별도로 관리한다.
- 실행 결과는 `.data/stt-bench/model-lab/runs/`에 불변 manifest로 추가한다.
- `npm run eval:speech-model-ledger`로 모든 캐시와 새 실행을 같은 정답으로 평가한다.
- 화자분리는 모델 원출력과 현재 제품 후처리 결과를 구분해 기록한다.

## 현재 서버 자원

- Artifact Registry: `faith-speech-model-lab` (Singapore)
- 비공개 실험 버킷: `faith-speech-model-lab-e80b5533-27b9-4476-9a4`
- 최소 권한 서비스 계정: `faith-speech-model-lab`
- CPU 작업: `faith-community1-cpu`, `faith-sherpa-sweep`

Cloud Run Job은 실행이 끝나면 인스턴스를 유지하지 않는다. 작업 정의와 저장된 이미지에는
컴퓨팅 비용이 없지만 Artifact Registry와 Cloud Storage 보관료는 계속 발생한다.

평균 CER나 화자 수만으로 선택하지 않는다. KTV 01:55의 진행자 호명, 첫 기자
자기소개, 04:55 기자 전환과 1인 음원의 화자 수를 별도 회귀 지표로 고정했다.

CAM++의 0.83~0.845는 8명을 만들지만 01:55를 틀리고, 0.85부터는 01:55를
맞추는 대신 서로 다른 두 기자를 합쳐 7명이 된다. 단일 임계값으로 둘을 동시에
해결할 수 없다는 결과이므로, 임계값만 조정하는 패치는 금지한다. CAM++ 0.85와
0.80의 이중 결과를 합치는 방법 또는 Community-1을 정밀 모드 기준으로 다음
fixture들에서 검증한다.

1인 발표 fixture `brief-rda-single-speaker`에서는 기존 ERes2Net, CAM++와
Community-1이 모두 원시 모델 단계부터 1명으로 통과했다. Community-1은 CPU에서
272.7초가 걸렸지만 GPU 속도는 이번 선택 기준에서 제외했다. 화면에 `사람 + 발화`
두 명이 보이는 문제는 명백한 1인 음원에서는 모델 과분리보다 표시/근거 라벨 단계
회귀를 먼저 확인한다.

전사는 `gpt-transcribe` 원문과 강제정렬 단어 근거가 모두 CER 0.0536, 핵심 구절
재현 80%였다. 예전 제품 줄 재구성 캐시는 CER 0.0566, 재현 40%로 악화되어
`뉴시스 김영록`, 마지막 `글쎄요`를 잃었다. PRIMARY 원문을 화면 대화의 불변
근거로 유지해야 하며 의미 모델이나 타이밍 전사가 본문을 다시 쓰면 안 된다.

SenseVoiceSmall INT8은 CPU 추론 26.9초, 약 $0.01로 빨랐지만 CER 0.1586,
핵심 구절 재현 40%라 본전사 후보에서 탈락했다. 저비용 초벌/검색 인덱스 후보로만
남긴다.

## 기존 KTV 저장본의 실패 단계 분리

2026-07-30 로컬 분석 저장본 `mtg-up-6992e7a7`도 모델 점수와 별도로 역추적했다.

- 01:55 기자 줄의 저장된 시작은 109.27초였지만 첫 실측 단어 `한국일보`는
  119.58초였다. 약 10.31초의 싱크 오차는 단어 타임스탬프가 아니라 화면이 줄
  시작값을 먼저 사용한 문제다. 단어 시각이 있으면 실측 첫 단어를 우선한다.
- 원 전사에는 `유시스 김영록입니다`가 남아 있지만 최종 대화에서는 자기소개 줄
  전체가 사라지고 298.26초의 질문부터 `화자 C`로 시작한다. `뉴시스` 오인식은
  STT 실패지만, `김영록`과 화자 소개까지 잃은 것은 대화 재구성 실패다.
- 원 전사의 `홍보수통수석`은 해당 구 실행의 STT 입력부터 잘못돼 있다. 반면 같은
  fixture의 현재 `gpt-transcribe` 기준선은 `이규연 홍보수석`을 보존하므로, 최신
  분석은 PRIMARY 원문을 고정하고 타이밍/의미 단계가 이를 덮어쓰지 않아야 한다.

따라서 한 회의에서 보이는 오류를 한 모델의 문제로 합산하지 않고 `PRIMARY STT`,
`단어 시각`, `음성 cluster`, `이름 매핑`, `최종 대화`, `재생 UI` 여섯 단계로
각각 기록한다.

## 정확도 우선 파이프라인 후보

1. `gpt-transcribe`의 원문을 PRIMARY로 고정하고, 강제정렬은 단어 시각만 추가한다.
2. 화자분리는 현재 두 fixture를 모두 통과한 Community-1을 정확도 우선 기준으로
   둔다. CAM++ 0.80/0.85 결과는 경계 불일치 탐지용 보조 신호로만 사용한다.
3. 이름은 음성 cluster 자체에 바로 붙이지 않는다. `기자님` 호명은 진행자,
   바로 뒤의 언론사+자기소개는 기자라는 대화 규칙으로 먼저 경계를 고정한 뒤
   이름을 매핑한다.
4. 후처리는 전체 본문을 재작성하지 않고, 낮은 확신 구간만 주변 음성과 문맥으로
   재검사한다. 수정 후보는 PRIMARY 원문과 나란히 보존한다.
5. 다음 채택 판단은 2인 대화, 겹침 발화, 잡음/원거리, 5~10인 기자회견 fixture를
   추가해 같은 장부에서 한다. 어떤 한 fixture라도 실제 화자 과병합 또는 1인
   과분리가 생기면 단독 채택하지 않는다.

같은 서버 실행에서 임계값만 여러 개 만든 manifest의 비용은 중복 합산하지 않았다.
실행 작업별 신규 Cloud Run 추론비 추정 합계는 $0.2836이며, 유료 모델 API 신규
호출은 0회다. Cloud Build, 저장소의 소액 비용은 이 합계에 포함하지 않는다.

## GPU 상태

이 프로젝트의 Cloud Run 비존 중복 L4 쿼터는 현재 0이며 사용 이력 부족으로 자동 증액
대상이 아니다. 2026-08-04에 지원 리전 다섯 곳에서 비용 없는 Job 정의 배포를
시도했지만 모두 실행 전에 quota 오류로 거절됐다. Compute Engine도 전역·지역 L4가
0이라 우회할 수 없다. 승인 뒤에는 Job 정의를 유지하고 실행할 때만 L4 1개를 할당하는
방식으로 운용한다. 상세 근거와 smoke 순서는 [`l4-on-demand.md`](./l4-on-demand.md)에
기록했다.

## 표면 정확도 개선 실험

의미·화자 문제와 분리해 `청크 경계`, `회의 내부 반복 표기`, `외부 근거가 필요한
고유명사` 세 종류로 판정한다.

- 청크 경계는 PRIMARY 청크 두 개와 독립 Whisper 단어 시각의 LCS를 비교한다.
  양쪽에 같은 앵커가 있고 PRIMARY에만 1~2개 되감기 단어가 끼었을 때만 삭제한다.
  정보보호 hard-set의 `마지막. 하겠습니다. 마지막으로` 1건을 고쳤고 정상 경계는
  그대로 유지했다. 추가 API 비용은 없다.
- 기관명은 PRIMARY와 독립 타이밍 전사 양쪽에서 같은 표기가 반복되고, 한 번 나온
  근접 오표기가 그 표기와 발음상 유일하게 대응할 때만 자동 보정한다. 실제 캐시에서
  `각기 정통부를 → 과기정통부를` 1건만 선택했고 청문회 자동 보정은 0건이었다.
- 인명은 두 전사가 같은 오답을 낼 수 있어 내부 다수결로 자동 변경하지 않는다.
  `김희정` 9초 구간은 `gpt-transcribe`, `gpt-4o-transcribe` 모두 사전 없이
  `김의정`으로 틀렸고, 출처에서 확인한 `김희정`을 넣은 경우에만 둘 다 맞혔다.

표적 재전사 10회 사전 예산은 $0.0088이었고 실제 호출도 그 범위 안에서 끝났다.
전체 파일 재전사 대신 의심 구간만 8~10초 다시 듣는 비용 구조는 유효하다. 다만
출처·참석자·사용자 확인에서 얻은 정답 후보가 없는 인명은 자동 수정하지 않고 추천으로
남겨야 한다. 공개 영상은 `출처 URL → 공식 자막/참석자 → 회의별 glossary` 경로를,
비공개 회의는 초대 명단·팀원 이름·사용자 확인 용어만 신뢰 근거로 사용한다.
